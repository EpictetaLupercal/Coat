# Coat 1.1.0 export validation

## Cause and correction

The previous exporter sliced every contour at all vertex Y coordinates on its level and merged only axis-aligned rectangles. This fragmented rotated rectangles and circles even though their source polygons were convex. It was not exporting render triangles directly.

Convex source contours without enclosed faces now bypass that partition entirely. Circles already store the analytically generated polygon vertices; rotation and nonuniform scaling modify those vertices, so export uses the actual transformed contour without resampling. Concavities and holes retain the existing even-odd slab algorithm. Compatible neighboring pieces are merged when their convex hull equals their combined area. No new dependency or project-format migration was introduced.

## Results

630 regression assertions passed on Windows. Tests cover convexity, plane winding, nondegenerate faces, brush/plane counts, footprint area, transformed vertices, read-only export, layers, holes, bridges, collinear cleanup, distant coordinates, SVG clipping and 1% zoom persistence/interactions. PNG output was inspected for the hole case.

The TrenchBroom connector independently parsed all eight generated Valve 220 maps and reconstructed their bounds and face counts:

| Fixture | Brushes | Planes per brush |
| --- | ---: | --- |
| Rectangle | 1 | 6 |
| Rectangle rotated 45 degrees | 1 | 6 |
| 12-sided circle | 1 | 14 |
| 24-sided circle | 1 | 26 |
| Scaled and rotated ellipse | 1 | 26 |
| Rotated convex pentagon | 1 | 7 |
| Rotated concave L | 3 | 6, 6, 5 |
| Rectangular hole | 4 | 6 each |

Fixtures are generated by the regression suite in `artifacts/tests/map-110/`. The concave merge is deterministic and greedy; it reduces fragmentation but is not a proof of globally minimal brush count. Rectangular pieces remain preferred for orthogonal contours when possible.

## Verification limits

Interactive import into the TrenchBroom application could not be confirmed: Windows UI automation failed to capture/control the file dialog reliably. Connector parsing is an independent geometry check, not proof of successful interactive import. BSP compilation was attempted through the connector but could not run because ericw-tools `qbsp` is not installed. No compiler pass or game-engine run is claimed.

## Fill semantics

Each face subtracts its immediately enclosed closed contours on the same level, using an even-odd compound path. Inner faces keep independent fill assignments and may themselves contain holes. Existing bridged boundary loops retain their own holes without subtracting them twice. This matches the exporter's innermost-face ownership rule; an unfilled inner face remains empty.
